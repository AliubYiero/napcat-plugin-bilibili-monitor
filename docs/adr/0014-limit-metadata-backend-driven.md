# ADR 0014: 上限元数据由后端下发

日期: 2026-10-20
状态: 已采纳

## 背景

上限 tab 需要渲染 `live` / `online` / `dyn` 三档的上下限与默认值, 并允许内联
编辑。当前这些常量分散在插件后端的三个上限服务里 (默认值还区分群聊/私聊),
WebUI 与 shared 无法直接 import 插件业务模块; 若在前端复制一份常量, 后端调整
默认值后必然漂移。

## 决策

1. **`GET /monitors/limits` 同时返回元数据与用量**: `meta` 含 `min` / `max` /
   三档的群聊与私聊默认值; `sessions` 含每个会话的三档已用与显式上限。
2. **前端不复制常量**, 输入范围、默认值标注与「恢复默认」文案全部由响应驱动。
3. **超管私聊显示无限**: 后端标记 `unlimited: true`, 前端展示 `∞` 并禁用编辑。
4. 写入仍走服务层的 `setXxxLimit` / `removeLimit`, 范围校验以后端为准, 前端只做
   即时输入约束。

## 理由

- 单一事实来源留在上限服务, 默认值调整不需要同步改 WebUI 与 shared。
- 前端拿到元数据即可渲染, 不必知道「群 5 / 私聊 1」这类业务规则。
- 后端仍保留范围校验, 前端约束只是体验优化, 不是安全边界。

## 后果

- `GET /monitors/limits` 的响应形状成为前后端契约, 变更需两侧同步并更新
  `docs/webui-config-pattern.md`。
- 前端必须处理元数据缺失或字段异常的情况 (回退为只读提示), 不得自行猜测默认值。
- 相关决策: ADR 0012 (写操作信任边界)、ADR 0013 (内存健康快照)。
