# ADR 0006: 会话启用开关默认开启

日期: 2026-09-08 (2026-10-20 修订: 由"群配置"推广为"会话配置")
状态: 已采纳

## 背景

插件以**会话**为单位提供启用开关 (群与好友/私聊各自独立)。未出现在配置中的会话, 其启用状态必须有一个明确语义: 默认开启还是默认关闭。

早期该开关是插件配置文件里的嵌套对象 `groupConfigs` (仅群); 模板化改造后, 会话配置移出配置文件, 由独立数据文件 `bilibiliSessionConfig.json` 承载, 且覆盖私聊会话 (见 ADR 0009 / 0010)。

## 决策

**默认开启**。判定式为宽松判定 `enabled !== false` (唯一入口 `sessionConfigService`):

- 缺失字段、缺失整条记录 (含"从未配置过该会话") → 视为启用;
- 仅显式 `enabled: false` 才禁用;
- 反向开关 (开播 @全体成员 `liveMentionAll`) 采取相反判定 `=== true`, 且仅群会话有效。

存储上**只持久化非默认值**: `enabled === false` / 群 `liveMentionAll === true` 才写进记录, 恢复默认即删除记录。

## 理由

- 零配置可用: 用户添加监控项后推送即时生效, 无需先去开关处启用一次。
- 监控类插件的打扰风险可控: 用户能收到推送恰恰是加了监控项的直接后果, 不会出现"配置了却收不到通知"的困惑。
- 只存非默认值使"缺记录"与"显式默认"不会分叉, 文件不随会话数无界膨胀。

## 后果

- 消息入口 (`messageHandler`) 在触发判定**之前**对群与私聊统一做会话门控短路; 业务层不再重复判定启用状态。
- 该语义是插件的显式声明, 相关文档 (`CONTEXT.md` / `config-pattern.md` / `store-pattern.md`) 中不得含糊表述; 若未来改为默认关闭, 需修订本 ADR 并同步判定与归一化逻辑。
- 开关修改入口是 WebUI 会话页 (逐个 / 批量) 与开播 @全体成员 指令; 会话级"启停"指令为可能的后续增强 (另立任务)。
